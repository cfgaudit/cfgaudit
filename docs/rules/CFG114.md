# CFG114: committed agent plugin or extension code runs from the repository

**Severity:** `error` (OpenCode plugin or tool) · `warn` (OpenCode 2 plugin directory with only a desktop part) · `info` (Copilot CLI project extension)
**OWASP:** [LLM04:2026 – Supply Chain](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM04_SupplyChain.md)
**Agents:** copilot, kilo-code, opencode

## What cfgaudit checks

Every JavaScript or TypeScript file in `.opencode/plugin/`, `.opencode/plugins/`, `.opencode/tool/` or `.opencode/tools/` (one level deep, `*.ts` and `*.js`, as OpenCode globs them). The same holds for Kilo Code, an OpenCode fork that reads `.kilocode/` and `.kilo/` in place of `.opencode/` ([#1056](https://github.com/cfgaudit/cfgaudit/issues/1056), v7.8.27 source): its `{plugin,plugins}/*.{ts,js}` and `{tool,tools}/*.{js,ts}` there are reported the same way, as `error`.

OpenCode imports these files from the repository itself. Measured with opencode 1.18.18 and a scratch `HOME`, each file writing a marker when imported:

| file | runs |
|------|------|
| `.opencode/plugin/x.ts`, `.opencode/plugin/x.js`, `.opencode/plugins/x.ts`, `.opencode/plugins/x.js` | during a bare `opencode debug config`, before any session |
| `.opencode/tool/x.ts`, `.opencode/tool/x.js`, `.opencode/tools/x.ts`, `.opencode/tools/x.js` | during `opencode debug agent <name>`, as soon as an agent loads |
| control: the same plugin under `notopencode/plugin/` | never |

No run asked anything. OpenCode has no workspace trust step, so opening a clone with OpenCode is enough to run the code with the user's own permissions.

## OpenCode 2 plugin directories

OpenCode 2 also loads a **folder** directly in `.opencode/plugin/` or `.opencode/plugins/` as a plugin ([#748](https://github.com/cfgaudit/cfgaudit/issues/748), `PluginSourceDirectory.discover` and `Host.resolve` in v2.2.6), and so does a `./` or `../` entry of the `plugin` or `plugins` key in `opencode.json`, resolved against the folder of that file. The folder's entry is resolved like a package:

- a `package.json` with a `name` and `exports` resolves through `exports`, and cfgaudit reports the `package.json`;
- otherwise the server part is `server` or `index` at the folder root (`.ts`, `.tsx`, `.js`, `.mjs`, `.cjs`, `.jsx`, or `server/index.*`), and cfgaudit reports that file;
- a folder with no server part but a `gui-experimental.cjs` or `.js` loads for the desktop app. That is a `warn`: whether the desktop app asks before running it is not measured;
- a folder with neither, for example a TUI-only one, is skipped, as OpenCode skips it.

This is read from the source, not measured against a running OpenCode 2, and OpenCode 1.x does not load a plugin folder. OpenCode 2 no longer reads `.opencode/tool/` or `.opencode/tools/`; those findings are for OpenCode 1.x. A symlinked folder is not followed.

## Copilot CLI project extensions

Copilot CLI runs `.github/extensions/<name>/extension.mjs` (or `.cjs` / `.js`) with Node.js, from the project as from `~/.copilot/extensions/` (#648). GitHub's docs: "Extensions execute on your computer with your privileges". Two gates stand in front of a project extension, read from the 1.0.95 bundle and the docs: extensions are an experimental feature (`--experimental` or `/experimental on`), and project extensions load only once the folder is trusted (in `-p` mode only with `GITHUB_COPILOT_PROMPT_MODE_EXTENSIONS=true`). That is why the finding is `info`: the code is committed and runs with the user's privileges, but only after the user has opted in twice.

## Why it is reported

This is the same class as [CFG047](CFG047.md) (a `folderOpen` task) and [CFG086](CFG086.md) (a hook on a zero-click event): repository content that executes because the project was opened. cfgaudit does not analyse the code; the finding is about the trigger, and it fires even when the plugin looks harmless, because the reader has to review it before the first run.

Committing a plugin for the team is a documented OpenCode workflow, so a finding here is often expected. Once the code is reviewed, list the file under `exclude-paths` in `.cfgaudit.yml` (for example `".opencode/plugin/notify.ts"`), or set `CFG114: warn` there if the repository commits plugins as a matter of course.

## Trigger example

```text
.opencode/
  plugin/
    notify.ts      ← CFG114
  tools/
    deploy.js      ← CFG114
```

## Safe alternative

Install plugins a contributor chooses in their user config (`~/.config/opencode/plugin/`) instead of the repository, or keep the committed plugin and review every change to it like any other code that runs on checkout.
