# CFG025 — custom organisation policy (require-deny / forbid-allow)

**Severity:** `error`
**OWASP:** [LLM03:2026 – Excessive Agency](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM03_ExcessiveAgency.md)
**Agents:** claude-code, devin

## What cfgaudit checks

CFG025 enforces an organisation's **own** permission policy, declared in [`.cfgaudit.yml`](../usage.md#configuration-file-cfgaudityml). Unlike the other rules (which encode universal CVE/hardening checks), CFG025 is **inert until you configure a `policy:` section**. It evaluates against the project's `permissions.allow` / `permissions.deny`.

```yaml
# .cfgaudit.yml
policy:
  # Commands that MUST be blocked by permissions.deny.
  require-deny:
    - "Bash(git commit:*)"
    - "Bash(git push:*)"
  # Commands that MUST NOT be grantable by permissions.allow.
  forbid-allow:
    - "Bash(git commit:*)"
    - "Bash(curl:*)"
```

- **`require-deny`** → `error` when no `permissions.deny` entry **covers** the command. This is the strong guarantee: in Claude Code `deny` beats `allow`, so a covered deny actually blocks it.
- **`forbid-allow`** → `error` when any `permissions.allow` entry **grants** the command (in whole or part).

### Containment-aware matching

Matching is not a plain string compare — broader patterns subsume narrower ones:

| Policy target | `require-deny` satisfied by a deny of | `forbid-allow` violated by an allow of |
|---------------|----------------------------------------|----------------------------------------|
| `Bash(git commit:*)` | `Bash(git commit:*)`, `Bash(git:*)`, `Bash(*)` | `Bash(git commit:*)`, `Bash(git:*)`, `Bash(*)`, or any `Bash(git commit …)` |

So a narrower deny (`Bash(git commit --amend)`) does **not** satisfy `require-deny: Bash(git commit:*)`, while any allow that grants even one `git commit` invocation violates `forbid-allow`.

Evaluated against the **project** `settings.json` (the committed artifact a CI policy applies to).

## Agent-neutral policy

A team that uses more than one agent writes the policy once under `deny` and the mapping form of `forbid-allow`, and CFG025 checks it against each agent's committed permission file (#1081):

```yaml
policy:
  deny:
    commands: ["git push"]          # word prefix: git push, git push origin main
    read: ["**/.env", "~/.ssh/**"]  # paths relative to the repository, or ~/
    write: ["src/generated/**"]
    fetch: ["*.example.com"]        # domains; *. for every subdomain
    mcp-tools: ["github:delete_*"]  # server:tool; the tool may be * or end in *
  forbid-allow:
    commands: ["curl"]
    mcp-tools: ["github:*"]
  agents: [claude-code, devin]      # optional
```

Without `agents`, the policy applies to every agent with configuration in the repository: Claude Code when `.claude/`, `CLAUDE.md` or `.mcp.json` exists, Devin CLI when `.devin/` exists, Cursor CLI when `.cursor/cli.json` exists, Qwen Code when `.qwen/` or `QWEN.md` exists, Grok when `.grok/` exists. An agent named under `agents` is checked even when it has no configuration yet, so a missing file is reported rather than skipped. Agents that read their permission rules from user settings only (Zed, Continue) get one [CFG118](CFG118.md) info finding instead. Any other name is rejected with exit 2 until cfgaudit can check that agent.

A missing deny is reported against the agent's file with the entry to add, in that agent's syntax:

| Category | Claude Code (`.claude/settings.json`) | Devin CLI (`.devin/config.json`) |
| --- | --- | --- |
| commands | `Bash(git push *)`; also covered by `Bash(git:*)`, `Bash(*)`, `Bash` | `Exec(git push)`; also covered by `Exec(git)`, `exec` |
| read | `Read(**/.env)`; also covered by `Read(.env)`, `Read(dir/**)`, `Read` | `Read(**/.env)`; also covered by `Read(dir/**)`, `read` |
| write | `Edit(src/generated/**)`; a `Read` deny of the path covers it too | `Write(src/generated/**)`; also covered by `edit` |
| fetch | `WebFetch(domain:*.example.com)`; also covered by `WebFetch(domain:*)`, `WebFetch` | `Fetch(https://*.example.com/*)`, or `Fetch(domain:example.com)` for one domain |
| mcp-tools | `mcp__github__delete_*`; also covered by `mcp__github`, `mcp__github__*`, `mcp__*` | `mcp__github__delete_*`; also covered by `mcp__github__*`, `mcp__*` |

Cursor CLI (`.cursor/cli.json`) is checked as the code of its package 2026.11.05-86047df behaves, read but not run, which differs from its documentation in two places:

| Category | Entry to add | Also covered by | Not covered by |
| --- | --- | --- | --- |
| commands | `Shell(git push)` | `Shell(git)`, `Shell(git:*)`, `Shell(git:push*)`, `Shell(*)`, and the same with `Bash(...)` | `Shell(git push *)` and `Shell(git:push)`, which let a bare `git push` or `git push origin` run |
| read | `Read(**/.env)` | `Read(**)`, `Read(**/.env*)` | `Read(.env)`, `Read(.env*)` and `Read(src/**)`: the CLI compares a pattern with the whole absolute path, so a relative pattern never matches, although its documentation shows `Read(.env*)` |
| write | `Write(**/src/generated/**)` | `Write(**)`, `Write(**/src/**)` | `Read(...)`: a Read deny does not block writes |
| mcp-tools | `Mcp(github:delete_*)` | `Mcp(github:*)`, `Mcp(*:*)`; case does not matter | |

Cursor CLI also adds `permissions` from `.claude/settings.json`, so a deny there counts when the CLI reads it the same way, and an allow there counts for `forbid-allow`. `deny.fetch` is not checked for it: a `WebFetch` deny only decides whether approval can be skipped, so [CFG118](CFG118.md) reports the category instead. A `.cursor/cli.json` in a subdirectory replaces the lists of the one above it when the CLI starts below it, and the root file replaces the user's lists; cfgaudit checks the root file only.

Qwen Code (`.qwen/settings.json`) and Grok (`.grok/config.toml`) are checked as their source behaves (qwen-code c2e77d1, grok-build 2bdd1d6):

| Category | Qwen Code | Grok |
| --- | --- | --- |
| commands | `Bash(git push)`; also `Bash(git push *)`, `Bash(git:*)`, `Bash`. `Shell(...)` works too | `Bash(git push)`; also `Bash(git *)`, `Bash(git:*)`, `Bash`. Not `Bash(git push *)`, which misses a bare `git push` |
| read | `Read(**/.env)`; also `Read(dir/**)`, `Read`. Not `Read(.env)`, one file | `Read(**/.env)`, and `Read(**/.ssh/**)` for `~/.ssh/**`: Grok keeps a leading `~/` as literal text |
| write | `Edit(/src/generated/**)`; also `Edit`. Not `Write(...)`, which skips the edit tool | `Edit(src/generated/**)` or `Write(...)`, one tool in Grok |
| fetch | `WebFetch(domain:example.com)`; also `WebFetch(example.com)`, `WebFetch` | `WebFetch(domain:example.com)`, `WebFetch`; a `*.` pattern matches nothing |
| mcp-tools | `mcp__github__delete_*`; also `mcp__github`, `mcp__*` | `MCPTool(github__delete_*)`; also `mcp__github`, `mcp__*`, `MCPTool` |

Both have no rule for subdomains alone, so `*.example.com` asks for the rule on `example.com`, which also blocks that host. Qwen's legacy `tools.exclude` counts as deny. Grok's structured `rules` count unless a compact `allow`, `deny` or `ask` array is set, because Grok then ignores them. Grok also adds `permissions` from `.claude/settings.json`, like Cursor CLI, and that includes `allow`, so `forbid-allow` looks there too. Grok ignores project rules in an untrusted folder; Qwen Code applies them unless folder trust is turned on.

For example, with this policy and no `.claude/settings.json` yet:

```yaml path=.cfgaudit.yml
policy:
  deny:
    commands: ["git push"]
  agents: [claude-code]
```

```text
.claude/settings.json [error] CFG025: policy deny.commands "git push": no permissions.deny entry covers it, so Claude Code does not block it; add "Bash(git push *)"
```

The neutral `forbid-allow` takes `commands` and `mcp-tools` only: whether an allowed path glob overlaps a forbidden one cannot be decided from the two strings. Claude Code skips an allow entry of `mcp__*`, so it does not count as granting a tool.

A deny in a committed file is a team default, not a guarantee: Claude Code and Devin CLI merge it with each contributor's own settings, Cursor CLI lets a nested `.cursor/cli.json` replace it, and a contributor can run the agent in a mode that skips prompts. The policy tells you the committed files say what the team agreed on.

## Example: "Claude may never run commit/push"

```yaml
policy:
  require-deny: ["Bash(git commit:*)", "Bash(git push:*)"]
  forbid-allow: ["Bash(git commit:*)", "Bash(git push:*)"]
```

## Limitation

Path globs are compared as strings: an entry covers a path when it is the same glob, `**`, or `dir/**` for a path below `dir`. A deny that covers the path in some other way is reported as missing, and the message names the entry that satisfies the check. For the Claude Code lists, matching covers the common Claude Code permission shapes (`Tool(cmd)`, `Tool(cmd:*)`, `Tool(cmd *)`, `Tool(*)`). Exotic glob forms inside the body are not interpreted.
