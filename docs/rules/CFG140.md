# CFG140: a Codex .codex/rules file blocks commands case-sensitively, or uses canonical_matching

**Severity:** `info`
**OWASP:** [LLM03:2026 – Excessive Agency](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM03_ExcessiveAgency.md)
**Agents:** codex

## What cfgaudit checks

Codex reads command rules from `.codex/rules/*.rules`: `prefix_rule(pattern=[...], decision="forbidden" | "prompt" | "allow")`. A rule matches the command's tokens **exactly** by default. Codex 0.167.0 adds `canonical_matching=True`, which compares every token of the rule caseless: NFD, full case folding, NFD ([#1642](https://github.com/cfgaudit/cfgaudit/issues/1642)).

Measured with `codex execpolicy check`:

| Rule | `git push` | `GIT push --force` | `git PUSH` |
|---|---|---|---|
| `prefix_rule(pattern=["git","push"], decision="forbidden")`, 0.167.0 | forbidden | no match | no match |
| the same with `canonical_matching=True`, 0.167.0 | forbidden | forbidden | forbidden |
| the same with `canonical_matching=True`, 0.166.0 | the rules file fails to parse | | |

CFG140 reports each project `.rules` file at most twice, both at `info`:

- **Exact `forbidden` or `prompt` rules.** One finding per file with the number of `forbidden` and `prompt` rules without `canonical_matching=True` and the first three of them with their lines. On macOS and Windows the file system ignores case, so `GIT push --force` starts the same `git` as `git push --force` and walks past a rule that matches exactly. On Linux it does not. cfgaudit cannot tell which system the reader uses, so this is a hint, not a warning.
- **`canonical_matching` in use.** Codex 0.166.0 and older do not know the keyword. When one rules file fails to parse, `load_exec_policy_with_warning` (`core/src/exec_policy.rs`, rust-v0.166.0) falls back to the requirements policy alone. Every user and project rule is dropped, the user's own `~/.codex/rules` included, and Codex only logs a warning. A committed file that uses the keyword therefore switches all command rules off for anyone on an older Codex.

`allow` rules are not reported: an exact allow grants less, not more. `canonical_matching=False` counts as exact, and as using the keyword. Only rules whose pattern is written literally are read, as for [CFG025](CFG025.md).

The [CFG025](CFG025.md) policy comparison reads the flag too. A canonical `forbidden` rule covers a policy `deny.commands` entry in any case, and a canonical `allow` rule grants a `forbid-allow.commands` entry in any case. cfgaudit compares with Go's simple case folding. It covers `GIT`, `PUSH` and `bAſh`, but not `ß` against `ss` or a combining accent, none of which occur in command names.

## Trigger example

```python
# .codex/rules/default.rules
prefix_rule(pattern=["git", "push"], decision="forbidden")
prefix_rule(pattern=["rm", "-rf"], decision="forbidden")
```

```text
.codex/rules/default.rules:1:1 [info] CFG140: 2 forbidden or prompt rules match case exactly: forbidden "git push" (line 1), forbidden "rm -rf" (line 2). On macOS and Windows, whose file systems ignore case, `GIT` starts the same program as `git` and walks past the rule. ...
```

## Measured

Of 25,100 corpus repositories, 45 commit `.codex/rules` files. 24 of them have `forbidden` rules (343 rules) and 22 have `prompt` rules. None uses `canonical_matching` yet. CFG140 gives 30 `info` findings, one per file with such rules.

## Fix

Once everyone who opens the repository runs Codex 0.167.0 or later, add `canonical_matching=True` to each `forbidden` and `prompt` rule:

```python
prefix_rule(pattern=["git", "push"], decision="forbidden", canonical_matching=True)
```

Until then, keep the rules exact. Add the case variants a user is likely to type as alternatives if that matters, for example `[["git", "GIT", "Git"], "push"]`. Do not use the keyword before every reader has upgraded, since an older Codex then drops every rule.
