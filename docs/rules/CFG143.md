# CFG143: an MCP server, hook or task fetches packages from a source the repository chooses

**Severity:** `error` (an extra index, a cleartext source, or TLS verification turned off) · `warn` (any other registry or index that is not the public one)
**OWASP:** [LLM04:2026 – Supply Chain](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM04_SupplyChain.md)
**OWASP MCP:** [MCP04:2025 – Software Supply Chain Attacks & Dependency Tampering](https://owasp.org/www-project-mcp-top-10/) — provisional (MCP Top 10 v0.1)
**Agents:** claude-code, cline, codex, continue, copilot, cursor, devin, devin-desktop, gemini-cli, goose, grok, junie, kimi-code, opencode, qwen-code, roo-code, vscode, zed

## What cfgaudit checks

A committed MCP launch such as `npx -y my-mcp@1.0.0` or `uvx my-mcp==1.0` fetches the server from npmjs.org or PyPI. One option or environment variable points the package manager somewhere else, and the code that runs then comes from whatever that host serves ([#1683](https://github.com/cfgaudit/cfgaudit/issues/1683)). A pinned version does not help: the other registry decides what `1.0.0` is.

CFG143 reads `npx`, `npm exec`/`install`, `pnpm dlx`/`pnpx`, `yarn dlx`, `bunx`/`bun x`, `uvx`, `uv tool run`, `uv run`, `uv pip install`, `uv add`, `pip install`, `python -m pip install` and `pipx run`/`install` in:

- each MCP server launch, with its `env`, in every agent's MCP configuration;
- each command site: hooks, helpers, status lines and skill or command `!` blocks, with a `VAR=value` or `env VAR=value` prefix;
- each VS Code task.

For `npx`, `uvx` and the other runners, only the options before the package count; what follows the package is the server's own command line. `pip install` and `npm install` take options anywhere.

| Source | Severity |
|---|---|
| an extra index: `--extra-index-url`, uv `--index`, `UV_EXTRA_INDEX_URL`, `UV_INDEX`, `PIP_EXTRA_INDEX_URL`. uv checks an extra index before PyPI, and pip takes the highest version from either, so a package of the same name there replaces the real one (dependency confusion) | `error` |
| a source over cleartext `http://`, other than `localhost` | `error` |
| TLS verification turned off: `--trusted-host`, `--allow-insecure-host`, `PIP_TRUSTED_HOST`, `UV_INSECURE_HOST`, `--strict-ssl=false`, `--no-strict-ssl`, `NPM_CONFIG_STRICT_SSL=false` | `error` |
| any other registry or index: `--registry`, `--@scope:registry`, `--index-url`/`-i`, `--default-index`, `--find-links`/`-f`, `NPM_CONFIG_REGISTRY`, `UV_INDEX_URL`, `UV_DEFAULT_INDEX`, `PIP_INDEX_URL`, `UV_FIND_LINKS`, `PIP_FIND_LINKS` | `warn` |

A company's own mirror is common, which is why a plain non-default registry is `warn`. An environment variable counts only for the tool it configures: `NPM_CONFIG_REGISTRY` for an `npx` launch, `UV_INDEX_URL` for a `uvx` one. One finding per command lists every source, at the highest severity among them.

**Not reported:**

- the public registries: `registry.npmjs.org`, `registry.yarnpkg.com`, `pypi.org`, `files.pythonhosted.org`;
- a value from a variable or a prompt (`--registry=${input:registry}`, `--index-url $PIP_INDEX`), which the user chooses;
- `--find-links` to a local folder;
- options after the package, which belong to the server (`npx -y @azure-devops/mcp --registry …`);
- options of other commands (`pip list`, `npm run build -- --registry …`, `docker run --registry …`).

[CFG010](CFG010.md) reports a package that is not pinned; [CFG098](CFG098.md) reports a plugin marketplace's npm source at a non-default registry. glsec reports the same options in CI scripts (GL069, GL079).

## Trigger example

```json path=.mcp.json
{
  "mcpServers": {
    "tools": {
      "command": "uvx",
      "args": ["--extra-index-url", "https://pkgs.internal.example/simple", "acme-mcp==1.4.0"]
    }
  }
}
```

```text
[error] CFG143: mcpServers.tools command fetches packages with "--extra-index-url https://pkgs.internal.example/simple" (an extra index: uv checks it before PyPI and pip takes the highest version from either, so a package of the same name there replaces the real one). The code that runs comes from wherever this source serves it, not from the public registry. Remove the option, or pin the package to a hash from a source you control
```

## Measured

On 25,100 corpus repositories (20,130 popular, 4,970 low-star), CFG143 gives no finding. The agent configurations that set a registry or an index all name the public one (`--registry https://registry.npmjs.org`, `--index https://pypi.org/simple`, `NPM_CONFIG_REGISTRY = "https://registry.npmjs.org/"`), take it from a prompt (`--registry=${input:registryString}`), or pass `--registry` to the server after the package name.

## Fix

Remove the option. If the package really lives on an internal registry, install it from there on the machine and start it by path, or pin it with a hash (`pip install --require-hashes`, an npm lockfile) so that another host cannot swap it.
