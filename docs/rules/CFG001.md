# CFG001 — `permissions.allow` contains unrestricted Bash pattern

**Severity:** `error`  
**OWASP:** [LLM03:2026 – Excessive Agency](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM03_ExcessiveAgency.md)  
**Agents:** claude-code

## What cfgaudit checks

cfgaudit flags `permissions.allow` entries that grant the agent permission to execute any shell command without a confirmation prompt. This covers the wildcard specifier `Bash(*)` / `Bash(**)` **and** the bare tool name `Bash` (no parentheses), which the [permissions docs](https://code.claude.com/docs/en/permissions) define as equivalent — "`Bash` matches all Bash commands … `Bash(*)` is equivalent to `Bash`". The same applies to **`PowerShell`** / `PowerShell(*)`, an equivalent arbitrary-command surface. An unrestricted grant maximises blast radius if the agent is manipulated via prompt injection or a malicious tool response.

An allow entry that a `permissions.deny` entry of the same file fully blocks is not reported: the identical entry, the bare tool name (`Bash` covers `Bash(*)`) or a broader pattern of the same tool. Claude Code checks deny before allow, so the allow entry has no effect; measured with 2.1.312, allow `Bash(touch:*)` with deny `Bash(touch:*)` blocked the command, and a bare deny `Bash` removed the tool (#1041). A partial overlap, allow `Bash` with deny `Bash(rm:*)`, is still reported. Only the same file counts, because cfgaudit cannot see the deny lists of the other settings layers, and a file Claude Code discards whole (CFG012) denies nothing.

## Trigger example

```json path=.claude/settings.json
{
  "permissions": {
    "allow": ["Bash(*)"]
  }
}
```

## Safe alternative

Scope permissions to the specific commands the agent needs:

```json
{
  "permissions": {
    "allow": ["Bash(go test ./...)", "Bash(make build)", "Bash(make lint)"]
  }
}
```

## Relationship to the SchemaStore schema

The [SchemaStore Claude Code settings schema](https://json.schemastore.org/claude-code-settings.json) already rejects `Bash(*)` — its `permissionRule` pattern requires the args inside parentheses to contain at least one character that is not `)`, `*`, or `?`. That check only fires in editors and tools that load the schema (VS Code IntelliSense, JSON validators in CI plugins, etc.) and only if the developer has not silenced the warning.

CFG001 catches the same misconfiguration in every other context: file-system audits, pre-commit hooks, scans of checked-out repos by people who do not use the schema-aware editor, and any future relaxation of the upstream schema. Treat the two as complementary, not redundant.
