# CFG144: an Antigravity CLI discovery manifest points outside the repository

**Severity:** `info`
**OWASP:** [LLM04:2026 – Supply Chain](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM04_SupplyChain.md)
**Agents:** antigravity

## What cfgaudit checks

Antigravity CLI reads four discovery manifests from `.agents/`: `skills.json`, `plugins.json`, `rules.json` and `agents.json` ([#1639](https://github.com/cfgaudit/cfgaudit/issues/1639), [docs](https://antigravity.google/docs/customization-discovery)). Each lists `entries`, folders or single items that add to the standard folders, and `inherits`, other manifests whose entries are added too:

```json
{
  "entries": [{ "path": "tools/agent-skills", "exclude": ["load-test"] }],
  "inherits": [{ "path": "vendor/shared/.agents/skills.json" }]
}
```

cfgaudit reads what an entry names inside the repository with the same rules as the standard folders. CFG144 reports an entry, in `entries` or `inherits`, that points outside the repository:

- an absolute path (`/home/dev/team/skills`, `C:\skills`);
- a relative path that leaves the repository through `../`;
- a path through a symbolic link that leads out of the repository.

What is there is not in the repository, so cfgaudit cannot check it, and on each machine that opens the repository it is whatever that machine has at that path. Antigravity CLI 1.5.2 and later skip such an entry in `skills.json` and `plugins.json` (CHANGELOG: "entries that point elsewhere through absolute paths, `../`, or symbolic links are skipped"). Earlier versions load it. For `rules.json` and `agents.json` the docs show such paths working (`"path": "../shared-rules"`), so those load what is there.

The finding is `info`: a team that keeps shared rules in a sibling checkout is common, and the entry is not an attack by itself.

**Not reported:**

- an entry inside the repository, which is scanned instead;
- an entry whose path does not exist in the repository, which loads nothing;
- the personal manifests in `~/.gemini/config/`, which are not in the repository.

Only the root `.agents/` is read, like `mcp_config.json` and `hooks.json`. A broken manifest is reported by [CFG109](CFG109.md).

## Trigger example

```json path=.agents/skills.json
{
  "entries": [{ "path": "../team-config/skills" }]
}
```

```text
[info] CFG144: skills.json entries[0].path "../team-config/skills" points outside the repository (it leaves the repository through ../). Antigravity CLI 1.5.2 and later skip it; earlier versions load what it names, and cfgaudit cannot check what is there. Keep the customizations in the repository, or let each user add the folder in their own ~/.gemini/config/skills.json
```

## Measured

On 25,100 corpus repositories, 15 commit at least one of the four manifests, and CFG144 reports 4 entries in 4 repositories: two absolute paths to a folder on the author's machine and two `../` paths to a sibling checkout, all in `skills.json`. The entries inside the repository name folders cfgaudit already reads (`skills/`, `.agents/skills`, `.gemini/skills`, `.agents/plugins/<name>`, `.agents/rules`), so the rest of the scan does not change there.

## Fix

Move the customizations into the repository and name them by a relative path, or leave the entry out and let each user add the folder in their own `~/.gemini/config/<kind>.json`.
