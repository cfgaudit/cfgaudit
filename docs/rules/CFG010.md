# CFG010 — MCP server uses an unpinned package or image version

**Severity:** `warn`
**OWASP:** [LLM04:2026 – Supply Chain](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM04_SupplyChain.md)
**OWASP Agentic:** [ASI04:2026 – Agentic Supply Chain Vulnerabilities](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/): LLM04:2026 now covers the model and data supply chain and refers the agentic one, "including MCP servers and tool registries", to ASI04
**OWASP MCP:** [MCP04:2025 – Software Supply Chain Attacks & Dependency Tampering](https://owasp.org/www-project-mcp-top-10/) — provisional (MCP Top 10 v0.1)
**Agents:** claude-code, cline, codex, continue, copilot, cursor, devin, devin-desktop, gemini-cli, grok, kimi-code, opencode, qwen-code, vscode, zed

## What cfgaudit checks

cfgaudit inspects each MCP server entry — both the inline `mcpServers` block in `settings.json` **and** the project's `.mcp.json` (the file `enableAllProjectMcpServers` / `enabledMcpjsonServers` auto-approve) — and flags any of:

1. **An arg ending in `@latest` or `:latest`** — covers both npm-style package pins (`@scope/pkg@latest`) and container image tags (`registry/image:latest`).
2. **An npm-style runner (`npx`, `pnpm dlx`, `yarn dlx`, `bunx`) whose first positional package argument has no `@<version>` suffix** — e.g. `npx -y @modelcontextprotocol/server-filesystem`. The package resolves to whatever the registry currently calls `latest`. Extra packages installed through a repeated package flag are also checked: every `--package <spec>` / `-p <spec>` / `--package=<spec>` / `-p=<spec>` value must carry an `@<version>` pin. When a package flag is present, the positional argument names the bin to execute from those packages (`npx -y -p @scope/pkg@1.2.3 pkg-bin`) and is not treated as a package.
3. **A Python package runner (`uvx`, `pipx run`) whose package argument has no version pin** — neither a PEP 508 specifier (`ruff==0.1.0`, `pkg>=1.2`, `pkg~=1.0`) nor the uvx `@<version>` form (`ruff@0.1.0`). Extra packages passed to `uvx --with <spec>` are checked with the same pin rules.

Local-path arguments (`./pkg`, `../pkg`, `/pkg`) are not flagged.

### Runners and option values (#1203)

- **pnpm and yarn** download a package only with `dlx`. `pnpm dev mcp` runs a `package.json` script and `pnpm -C packages/server exec node dist/mcp.js` a local binary, both pinned by the lockfile, so they are not reported. The values of `-C`, `--dir`, `--filter`, `-F` and `--cwd` are skipped when looking for `dlx`. `pnpx` is read as `pnpm dlx`.
- **uv option values** are not the package: `--python` / `-p`, `--python-preference`, `--refresh-package`, `--index`, `--index-url`, `--extra-index-url`, `--constraint`, `--overrides`, `--directory` and `--project`.
- **`uvx --from <source>`** names the package, and the positional after it is the command the package provides. A local source (a path or a variable such as `${CLAUDE_PLUGIN_ROOT}`) installs nothing from the index and is not reported.
- **A git source** (`git+https://...`) is pinned by a revision, and the message suggests one: `git+https://github.com/my-org/my-server@<commit-sha>`, before a `#subdirectory=` fragment if there is one.

In JSON files the finding points at the `args` element that holds the package, also when the server is named like its package.

Found in the pre-release corpus run for v1.20.0 on 10,034 repositories. Whether `npx` or `bunx` without `-y` should be reported for a package the project already lists as a dependency is still open in #1203.

An upstream compromise of an unpinned dependency silently propagates to every developer who reloads the agent — there is no SCA tooling between the registry and the MCP server.

## Trigger example

```json path=.mcp.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem@latest", "/tmp"]
    }
  }
}
```

## Safe alternative

Pin to an exact version:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem@1.2.3", "/tmp"]
    }
  }
}
```

For container images, pin to an immutable digest where possible:

```text
ghcr.io/owner/server@sha256:abcd…
```
