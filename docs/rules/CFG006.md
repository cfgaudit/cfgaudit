# CFG006 — `permissions.deny` is absent or empty

**Severity:** `warn`
**OWASP:** [LLM03:2026 – Excessive Agency](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM03_ExcessiveAgency.md)
**Agents:** claude-code

## What cfgaudit checks

cfgaudit flags any `settings.json` that defines a `permissions` block without a non-empty `deny` list. Without explicit denials, no rule blocks destructive operations such as `rm -rf`, `git push --force`, or arbitrary network calls — even when an `allow` entry is narrowly scoped, an unrelated default-allowed tool (or a future broadening of the allow list) can still reach them.

A denylist is the only mechanism that survives well-intentioned allow-list expansion, so it acts as a defense-in-depth guardrail rather than a primary control.

### When the deny list is the only gate (#1193)

The finding needs one of two things, because without them everything the allow list does not name still prompts and a deny list changes nothing:

- **A whole-tool grant** of a tool a deny list narrows (`Bash`, `Read`, `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `WebFetch`): the bare name (`"Bash"`) or a wildcard-only specifier (`"Bash(*)"`, `"Read(**)"`). A bare `WebSearch`, `Grep`, `Glob` or MCP tool name does not count.
- **A permissive mode:** `defaultMode` `auto`, `bypassPermissions` or `dontAsk`.

A narrow allow list such as `["Bash(npm run lint:*)", "WebFetch(domain:docs.example.com)"]` is not reported, and neither is a `permissions` block that allows nothing. A committed `.claude/settings.local.json` is not reported either: it is a history of "always allow" answers, a shared deny list belongs in `settings.json`, and [CFG013](CFG013.md) reports the committed file. A file Claude Code discards whole ([CFG012](CFG012.md)) is still reported, because its deny list is on paper only.

In the pre-release corpus run for v1.20.0 on 10,034 repositories, 341 of 405 findings were narrow allow lists, and 141 were committed `settings.local.json` files.

A deny list that is present in the file but not in force counts as absent. If the file carries a top-level value whose type the schema rejects, Claude Code discards the whole file (see [CFG012](CFG012.md)), so its deny entries never load; CFG006 then fires and names the key responsible. The same applies to `settings.local.json`, which normally inherits the project deny list: when the project `settings.json` is discarded, there is nothing to inherit.

## Trigger example

```json path=.claude/settings.json
{
  "permissions": {
    "allow": ["Bash"]
  }
}
```

## Safe alternative

```json
{
  "permissions": {
    "allow": ["Bash"],
    "deny": [
      "Bash(rm *)",
      "Bash(git push --force*)",
      "Bash(curl *)",
      "Bash(wget *)"
    ]
  }
}
```
