# CFG042 — `permissions.deny` does not restrict private key / certificate files

**Severity:** `error` · `warn` (the deny list guards no secret file yet, or the class is partly covered)
**OWASP:** [LLM02:2026 – Sensitive Information Disclosure](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM02_SensitiveInformationDisclosure.md)
**Agents:** claude-code

## What cfgaudit checks

Private-key and certificate files expose cryptographic material that cannot be rotated without replacing the associated infrastructure. cfgaudit flags a `permissions.deny` block that **exists** but does not cover these formats:

`*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`

The finding lists exactly which extensions are uncovered, so partial coverage (e.g. only `*.pem` present) still reports the remaining gaps. A wildcard like `Read(**/*.pem)` counts as covering `.pem`. A completely absent `permissions.deny` block is reported by CFG006, not here.

A **deny-all** entry suppresses this finding entirely: `Read(*)` / `Read(**)` / `Read(**/*)` (any version), or the bare `"*"` deny-all-tools glob on Claude Code **≥ 2.1.166** (a no-op on older releases, so the finding still fires there; treated as covering when the version is unknown).

## Severity (#1172)

`error` when the deny list already guards secret files (a `Read`, `Edit`, `Grep` or `Glob` rule on a credential path, or the bare tool) and misses this class, and in `auto` or `bypassPermissions` mode, where nothing else stops a read. `warn` when the deny list guards no secret file at all, because it was written for something else, such as blocking `git push`: without any deny list the file would get only one CFG006 warning, and adding an unrelated deny entry should not turn that into three or four errors. `warn` also when the class is partly covered, with the missing parts named. In the pre-release corpus run for v1.20.0 on 10,034 repositories, 65 of the 110 settings files these rules reported were of that kind.

## Trigger example

```json path=.claude/settings.json
{
  "permissions": {
    "deny": ["Read(.env)", "Read(**/*.pem)"]
  }
}
```

→ `error` (`.key`, `.p12`, `.pfx`, `.jks` still uncovered).

## Safe alternative

```json
{
  "permissions": {
    "deny": [
      "Read(**/*.pem)",
      "Read(**/*.key)",
      "Read(**/*.p12)",
      "Read(**/*.pfx)",
      "Read(**/*.jks)"
    ]
  }
}
```
