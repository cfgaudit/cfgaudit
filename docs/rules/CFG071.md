# CFG071 — model/provider base URL sends the API key over cleartext

**Severity:** `error` (a remote host) · `warn` (a host on a private network)
**OWASP:** [LLM02:2026 – Sensitive Information Disclosure](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM02_SensitiveInformationDisclosure.md)
**Agents:** codex, continue, junie, opencode

## What cfgaudit checks

Multi-provider AI tools let you point a model at a custom endpoint via a base URL — the provider API key is sent there. cfgaudit flags such a base URL when it uses **cleartext (`http://` / `ws://`) to a non-loopback host**, because the key then travels unencrypted to a remote endpoint:

- **Continue** — `models[].apiBase` and `data[].destination` in `.continue/config.yaml`
- **Codex** — `chatgpt_base_url` and `[model_providers.<name>].base_url` in `~/.codex/config.toml`
- **OpenCode** — a provider or model base URL in a committed `opencode.json` (or `opencode.jsonc`, `.opencode/opencode.json(c)`), [#779](https://github.com/cfgaudit/cfgaudit/issues/779). In the v1 spelling that is `provider.<id>.api`, which replaces `provider.<id>.options.baseURL`, and per model `models.<m>.provider.api`, which replaces `models.<m>.options.baseURL` (`v1/config/migrate.ts` in v2.2.6). In the v2 spelling it is `providers.<id>.settings.baseURL` and `providers.<id>.models.<m>.settings.baseURL`. Since 2.1 a provider base URL replaces the catalog endpoint of every model of that provider, the built-in `opencode` and `opencode-go` ones included (`config/plugin/provider.ts`), so one committed key redirects all of them. A value written as `{env:NAME}` is not read.

This is the multi-provider analogue of [CFG005](CFG005.md) (`ANTHROPIC_BASE_URL`).

### A host on a private network is a warning (#779)

Most cleartext base URLs point at a model server on the author's own network: Ollama, LM Studio or llama.cpp on another machine of the LAN, a Docker host, or a gateway inside a cluster. Such a server often takes no key at all. The key, when there is one, and every prompt still cross that network unencrypted, so these are reported as `warn` instead of `error`. That covers:

- a private, shared (CGNAT, `100.64.0.0/10`) or link-local address;
- a name without a dot (`llama_server`, `agent-gateway`);
- a name under a local-only suffix: `.local`, `.lan`, `.internal` (including `host.docker.internal`), `.home.arpa`, `.localdomain`, `.intranet`, `.home`, `.consul`, `.cluster.local`.

A host filled in on the reader's machine is not read: `$NAME`, OpenCode's `{env:NAME}`, and placeholders such as `<host>` or `__HOST__`.

In a ranked GitHub code search sample of 486 OpenCode configs with a `baseURL`, the OpenCode support added 90 cleartext findings before this split. 72 of them were private-network hosts and 9 were placeholders.

### Why only cleartext

A Continue `data` entry names where session content is exported to, so the same cleartext test applies, and what travels there is the session rather than the API key. When the entry also sets `level: all`, which the schema distinguishes from `noCode` precisely because it includes code, the message says so.

Only cleartext-to-remote is reported here, for the reason below and one more from measurement: the single real `data` block in a 108-config sample points at a `file://` path on the author's own machine. A finding on any non-default destination would have been wrong on the only occurrence there is.

Unlike Claude Code (whose only valid endpoint is `api.anthropic.com`), Continue, Codex and OpenCode are **multi-provider by design** — Azure OpenAI, OpenRouter, internal gateways, and local Ollama are all legitimate custom endpoints. So a non-default endpoint is **not** flagged on its own; only the unambiguous cleartext-to-remote case (key sent in plaintext) is. `https://`/`wss://` endpoints and loopback addresses are not flagged.

## Trigger example

```yaml path=.continue/config.yaml
models:
  - name: gpt
    provider: openai
    apiBase: http://gateway.internal.example/v1
    apiKey: ${{ secrets.OPENAI_API_KEY }}
```

→ `error` (the key is sent over cleartext `http://` to a remote host).

## Safe alternative

```yaml
models:
  - name: gpt
    provider: openai
    apiBase: https://gateway.internal.example/v1
```

(A loopback endpoint such as `http://localhost:11434/v1` for a local Ollama is also fine.)
