# CFG106 — a committed Codex config grants browser or desktop-application access

**Severity:** `error` (`full_cdp_access`, `computer_use.default_app_access`) · `warn` (everything else in the two tables)
**OWASP:** [LLM06:2025 – Excessive Agency](https://owasp.org/www-project-top-10-for-large-language-model-applications/2025/LLM06_2025-Excessive_Agency.html)

## What cfgaudit checks

The `[browser_use]` and `[computer_use]` tables Codex added on 2026-08-21, for values set to `allow`.

```toml
# .codex/config.toml — committed
[browser_use]
allow_history_access = true            # CFG106 (warn)

[browser_use.default_origin_policy]
access = "allow"                       # CFG106 (warn)
full_cdp_access = "allow"              # CFG106 (error)

[browser_use.origins."https://intranet.example.com"]
uploads = "allow"                      # CFG106 (warn)

[computer_use]
default_app_access = "allow"           # CFG106 (error)

[computer_use.macos.bundle_ids]
"com.apple.Terminal" = "allow"         # CFG106 (warn)
```

Every policy value is `AllowDenyRequirementToml`, an enum of exactly `allow` and `deny`. There is no `ask` middle state, so `allow` is unambiguously the weakening direction and `deny` is hardening and never reported.

**`full_cdp_access`** is the sharp one: full Chrome DevTools Protocol access to an origin is script execution, cookie and storage access inside the browser session, granted by a file in the repository rather than by the person browsing. **`computer_use.default_app_access`** is the blanket form of desktop control: every application on the machine, rather than a named one.

## Scope, verified at the artifact

Neither table is on Codex's `PROJECT_LOCAL_CONFIG_DENYLIST`. The project-layer sanitizer strips only `features.respect_system_proxy` and two TUI permission-mode keybindings, the latter with the comment:

> // Repository contents must not turn an ordinary key into a permission increase.

Upstream draws that line around two keybindings and leaves these tables readable from the same file.

Verified end to end rather than inferred from the loader. Against codex `0.150.0-alpha.7`, with an isolated `CODEX_HOME` and a scratch repository, the effective config read through the app server (`config/read` with the repository as `cwd`) came back carrying the repository's own values:

```json
"browser_use": {"allow_history_access": true,
                "origins": {"https://marker.example.com": {"full_cdp_access": "allow", …}}}
```

with `model_provider` (denylisted) `null` and `approval_policy` (an ordinary project key) applied, as controls. With the trust entry removed, the whole layer contributes nothing — the same folder-trust caveat CFG063 and CFG064 carry.

## Version boundary, measured

| Build | Config surface |
|---|---|
| 0.147.0 | field absent |
| 0.149.0 (npm `latest` on 2026-08-23) | field absent |
| 0.150.0-alpha.7 | present, repository values honoured |

So on today's stable a committed block is **inert**. No `MinVersion` gate is needed and none is used: the rule is presence-based, and a build without the surface has no such config to read. The rule ships ahead of stable because the file is committed now and the user upgrades into it later, the same reasoning CFG098's `archive` case shipped on.

## What is not reported

`deny` in any position. The `access` / `downloads` / `uploads` keys of an origin whose policy is absent. The whole `[browser_use]` table when it only narrows. cfgaudit also does not claim the grant suppresses a prompt in the client: `config/read` shows the repository's value reaching the consumer boundary, and the browser and computer use tools live in the app, so no message says anything about prompts being skipped.

## Fix

Name the origins and applications the project actually needs, with `deny` for the rest, or leave the tables out of the committed file entirely and let each user grant what they want in `~/.codex/config.toml`.
