# CFG145: an agent hook prints the environment or a secret into the model's context

**Severity:** `error` (the hook's stdout, or an output field that the agent passes on, reaches the model) · `warn` (its stdout shows in transcript mode, or a script started by a context hook turns on `set -x`)
**OWASP:** [LLM02:2026 – Sensitive Information Disclosure](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM02_SensitiveInformationDisclosure.md)
**Agents:** antigravity, claude-code, cline, codex, copilot, cursor, devin, gemini-cli, goose, grok, qwen-code, vscode

## What cfgaudit checks

What some hooks print does not go to a log; it goes to the model ([#1685](https://github.com/cfgaudit/cfgaudit/issues/1685)). Claude Code 2.1.325 describes, for each hook event, what happens to its output on exit code 0:

| Event | stdout on exit code 0 | Severity |
|---|---|---|
| `SessionStart`, `UserPromptSubmit`, `UserPromptExpansion` | "shown to Claude" | `error` |
| `PostModelSwitch` | "shown to Claude on the next request" | `error` |
| any event whose command writes a JSON `additionalContext` | "Text injected into model context" | `error` |
| `PostToolUse`, `PostToolUseFailure`, `PermissionDenied` | "shown in transcript mode (ctrl+o)" | `warn` |
| `PreToolUse`, `Notification`, `Stop`, `SubagentStop` and the others | not shown | not reported |

A hook that prints the environment there sends every variable, API keys and tokens included, to the model provider with the next request and into the session transcript.

CFG145 reads the Claude Code hooks of `settings.json`, `settings.local.json`, plugin `hooks/hooks.json` and skill, command and subagent frontmatter, and each shell script such a hook starts, line by line. It reports a command that writes to stdout:

- **the whole environment:** `printenv` without a name, `env` without a command to run, `export -p`, or `cat /proc/*/environ` (also `/proc/self/environ`, `/proc/$$/environ`), alone or through a pipe that passes it on (`sort`, `head`, `grep -i token`, `grep -v PATH`);
- **a secret-named variable:** `echo`, `printf` or `printenv` of a name ending in `_TOKEN`, `_SECRET`, `_PASSWORD`, `_API_KEY`, `_CREDENTIALS` and the like, or one of those names alone (`$API_KEY`, `$TOKEN`);
- **an environment dump in a printed substitution:** `echo "$(env)"`, `jq --arg c "$(printenv)"`.

### Other agents

Most agents pass only named JSON output fields to the model, and drop plain stdout or show it to the user ([#1780](https://github.com/cfgaudit/cfgaudit/issues/1780)). For them CFG145 reports a dump or a secret on a command line that writes one of those fields, in an event that passes it on: `echo "{\"additionalContext\": \"$GITHUB_TOKEN\"}"`, `jq -n --arg c "$(env)" '{additionalContext: $c}'`. The field has to be a JSON or jq key on the same line.

| Agent (version read) | Plain stdout reaches the model in | Fields that reach the model, and in which events |
|---|---|---|
| Codex (rust-v0.169.0, `codex-rs/hooks/src/events`) | `SessionStart`, `SubagentStart`, `UserPromptSubmit` | `additionalContext`: `PreToolUse`, `PostToolUse`; `reason`: `PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop` |
| Qwen Code (v0.27.4, `hookRunner.ts` `PLAIN_TEXT_CONTEXT_EVENTS`) | `SessionStart`, `UserPromptSubmit`, `UserPromptExpansion` | `additionalContext`: tool events, `PostToolBatch`, `SubagentStart`, `PreCompact`; `reason`: blocking events |
| Gemini CLI (v0.68.0, `hookRunner.ts`: plain stdout becomes a `systemMessage` for the user) | none | `additionalContext`: `SessionStart`, `BeforeAgent`, `AfterTool`; `reason`: `AfterAgent`, `BeforeTool`, `AfterTool` |
| Cursor ([hooks docs](https://cursor.com/docs/agent/hooks)) | none | `additional_context`: `sessionStart`, `postToolUse`, `postToolUseFailure`; `agent_message`: `preToolUse`, `beforeShellExecution`, `beforeMCPExecution`; `followup_message`: `stop`, `subagentStop`; `updated_mcp_tool_output`: `postToolUse` |
| Copilot CLI and VS Code, `.github/hooks` ([hooks reference](https://docs.github.com/en/copilot/reference/hooks-configuration), CLI changelog 1.0.11 and 1.0.65) | none | `additionalContext`: `sessionStart`, `userPromptSubmitted`, `postToolUse`, `postToolUseFailure`, `notification`, `subagentStart`; `modifiedResult`: `postToolUse`; `permissionDecisionReason`: `preToolUse`; `reason`: `agentStop`, `subagentStop` |
| Devin CLI ([hooks docs](https://docs.devin.ai/cli/extensibility/hooks/overview)) | none documented | `additionalContext`: `SessionStart`, `UserPromptSubmit`, `PostToolUse`; `reason`: `PreToolUse` |
| Antigravity ([hooks docs](https://antigravity.google/docs/hooks)) | none (output is JSON) | `injectSteps` `systemMessage`, `userMessage`, `ephemeralMessage`: `SessionStart`, `PreInvocation`; `reason`: `PreToolUse`, `Stop` |
| Grok Build (`xai-org/grok-build` main, `xai-grok-hooks`) | none | `additionalContext`: tool and stop events; `reason`, `permissionDecisionReason`, `updatedToolOutput`, `updatedMCPToolOutput`: gate events. Event names in any case or with underscores |
| goose (v1.59.1, `crates/goose/src/hooks`) | none | `reason` of a block: `PreToolUse`, `Stop` |
| Cline (v4.1.26, `hooks-adapter.ts`) | none | `contextModification`: `TaskStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse` |

Not covered: Continue v2.0.0 loads hooks but never fires an event. Devin Desktop documents no output field that reaches the model, only stderr of a pre-hook that exits with code 2. Copilot's `userPromptSubmitted` is in the table because the CLI changelog (1.0.65) says its `additionalContext` reaches the model, while the reference says command-hook output is dropped. Gemini, Qwen Code and Codex also send stderr to the model when a blocking hook exits with code 2. CFG145 does not read exit codes, so that path is not covered.

### xtrace

In a shell script started by a Claude Code hook from the first table rows, `set -x` (also `set -o xtrace` and a flag bundle such as `set -euxo pipefail`) is `warn`. The shell then prints every command with its variables expanded to stderr. Claude Code shows the hook's stderr to the user when the hook fails, secrets included. stderr does not reach the model.

**Not reported:**

- a single variable that is not a secret (`printenv HOME`, `echo "$CLAUDE_PROJECT_DIR"`);
- `env` used to run a command (`env FOO=bar cmd`, `env -i PATH=/usr/bin make`);
- output sent to a file, `/dev/null` or stderr (`printenv > /tmp/env.txt`, `printenv >&2`), or to another command (`echo "$GITHUB_TOKEN" | gh auth login --with-token`);
- a dump piped into a count, a quiet `grep` or a `grep` for a name that is not a secret (`env | wc -l`, `env | grep -q CI`, `env | grep ^PATH=`);
- a dump piped to the network, which [CFG038](CFG038.md) reports;
- a reference the shell does not expand to the value: in single quotes, `${#TOKEN}` (its length) and `${TOKEN:+set}`;
- the hooks of Continue and Devin Desktop, whose hook output does not reach the model (below).

## Trigger example

```json path=.claude/settings.json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [{ "type": "command", "command": "echo \"token: $GITHUB_TOKEN\"" }] }
    ]
  }
}
```

```text
[error] CFG145: hooks.SessionStart command prints $GITHUB_TOKEN: Claude Code adds the stdout of a SessionStart hook to the model's context, so the value goes to the model provider and into the session transcript. Print only what the session needs, never the environment or a secret
```

## Measured

On 25,100 corpus repositories, CFG145 reports nothing, for Claude Code and for the other agents. In the other agents' hook files a text search finds only `"env"` objects. The candidates in committed Claude Code hooks are comments, `env` used as a wrapper, `printenv` in permission rules, and a direnv hook that writes the environment to a file (`env -0 >"$raw"`), which stays quiet as it should.

## Safe alternative

Print only what the session needs: the branch, the project's status, a short note. To check that a secret is set, print whether it is, not its value (`[ -n "$GITHUB_TOKEN" ] && echo "token set"`). Keep debugging output such as `set -x` out of committed hooks, or send it to a file that is not committed.
