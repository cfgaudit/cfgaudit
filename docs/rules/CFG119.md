# CFG119: a script started by an auto-run hook or task carries the markers of a malicious payload

**Severity:** `error` · `warn` (one marker, started from several tools)
**OWASP:** [LLM04:2026 – Supply Chain](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM04_SupplyChain.md)
**Agents:** claude-code, codex, continue, copilot, cursor, devin, gemini-cli, grok, opencode, qwen-code, vscode, zed

## What cfgaudit checks

A committed command that runs without anyone asking for it can start a script from the repository: a Claude Code `SessionStart` hook running `node .tooling/start.mjs`, a VS Code task with `runOptions.runOn: "folderOpen"` running `bash scripts/setup.sh`, an MCP server launched as `python tools/server.py`, or the hooks of the other agents cfgaudit reads. The command-content rules see only the command line, so a payload moved into such a script passes them. cfgaudit reads the script (#1217), without running it, and CFG119 looks in it for the markers of a malicious payload:

| Marker | What it matches |
|---|---|
| Obfuscation | 30 or more identifiers of the form an obfuscator gives every variable, `_0x` plus hex digits |
| Download and run | the URL of a release asset, an archive, a binary or a runtime installer, together with code that starts a process or makes a file executable |
| Credential hunt | access-token prefixes (`ghp_`, `ghs_`, `gho_`, `github_pat_`, `npm_`, `AKIA`, `xox?-`) or credential files (`.npmrc`, `.aws/credentials`, `.docker/config.json`, `.git-credentials`, `.ssh/id_`), together with network code |
| Environment dump | `JSON.stringify(process.env)`, `Object.keys(process.env)`, `os.environ.items()` or 50 or more `process.env` reads, together with network code |

- **error:** obfuscation together with any other marker, or a download-and-run step together with a credential hunt.
- **warn:** one marker in a script that the configuration of two or more tools starts, such as a VS Code folder-open task and an agent hook. Starting the same script from several tools is rare in a legitimate repository and the usual way an implant makes sure it runs whichever tool is opened first.

A launcher that starts a process and names a file next to it (`const payload = "index.js"`) is followed one step further, so a small loader that downloads a runtime to run the payload beside it does not hide the payload.

The script is resolved from the command: an interpreter (`node`, `bun run`, `deno run`, `npx tsx`, `python`, `bash`, `sh`, `pwsh -File`, `ruby`, `perl`, `php`) followed by a path, or a script path run directly (`./scripts/x.sh`), with `$CLAUDE_PROJECT_DIR` and `${workspaceFolder}` read as the repository root. A path outside the repository, a path with any other variable, a binary file and a file over 4 MB are not read. Package scripts (`npm run dev`) are not resolved: their code is the project's own build.

## Trigger example

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [{ "type": "command", "command": "node .tooling/start.mjs" }] }
    ]
  }
}
```

with `.tooling/start.mjs` an obfuscated bundle (`var _0x4d2c=...` throughout) that contains token patterns such as `ghs_` and sends data with `https.request`:

```text
.tooling/start.mjs [error] CFG119: script .tooling/start.mjs, started by the hooks.SessionStart command, carries the markers of a malicious payload: it is obfuscated (412 _0x identifiers); it looks for access tokens or credential files and talks to the network. A committed script that runs when the repository is opened must not hide what it does; read it before you open the repository with an agent or editor, and if nobody in the project added it, treat the repository as compromised
```

## Measured

The pre-release corpus run for v1.20.0 on 10,034 popular repositories that commit agent configuration found one implant, byte-identical in two unrelated projects and committed under the name of the Actions bot: a loader started by a Claude Code `SessionStart` hook and a VS Code folder-open task, which downloads a runtime and runs an obfuscated bundle that collects tokens and the environment. Before this rule, cfgaudit reported only CFG047 for the task and CFG067 for the hook, worded the same as for ordinary build tasks. CFG119 reports the bundle at error and the loader at warn in both projects, and nothing anywhere else in the corpus, which holds many large legitimate JavaScript files in skills and plugins (chart libraries, browser helpers, dashboards).

## Fix

Open the script and read it before you open the repository with an agent or an editor that runs its tasks. If nobody in the project added it, treat the repository as compromised: remove the files and the hook or task that starts them, rotate the tokens of everyone who opened it, and find out how the commit got in.
