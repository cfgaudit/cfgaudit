# CFG138: a browser MCP server attached to the user's own browser or profile

**Severity:** `warn` (attaches to the running browser, the user's profile, or an endpoint on another host) · `info` (a debugging endpoint on this machine)
**OWASP:** [LLM03:2026 – Excessive Agency](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM03_ExcessiveAgency.md)
**OWASP MCP:** [MCP02:2025 – Privilege Escalation via Scope Creep](https://owasp.org/www-project-mcp-top-10/), provisional (MCP Top 10 v0.1)
**Agents:** claude-code, cline, codex, continue, copilot, cursor, devin, devin-desktop, gemini-cli, goose, grok, junie, kimi-code, opencode, qwen-code, roo-code, vscode, zed

## What cfgaudit checks

A browser MCP server normally starts a browser of its own with an empty profile. A few switches make it use a browser the user already has instead. The agent then acts with the user's cookies and logged-in sessions: mail, admin consoles, banking. A committed MCP config that sets one of them hands those sessions to every agent session in the repository.

cfgaudit reads the `args` (and, for Playwright MCP, the `env`) of known browser MCP servers: Playwright MCP (`@playwright/mcp`), Chrome DevTools MCP (`chrome-devtools-mcp`), Firefox DevTools MCP, browser-use and the Puppeteer servers. Other servers are not read, because the switch names are generic: `--extension` means something else elsewhere.

| Switch | Severity | Why |
|---|---|---|
| `--extension` (Playwright MCP, also `PLAYWRIGHT_MCP_EXTENSION`) | `warn` | connects through the browser extension to the browser the user is running |
| `--autoConnect` / `--auto-connect` (Chrome DevTools MCP) | `warn` | connects to the Chrome the user is running |
| `--user-data-dir` on a real browser profile (also `PLAYWRIGHT_MCP_USER_DATA_DIR`, and `--chrome-arg=--user-data-dir=...`) | `warn` | starts the browser with the user's own profile: Chrome, Chromium, Edge, Brave or Firefox under `~/.config`, `~/.mozilla`, `~/Library/Application Support`, `AppData` or `%LOCALAPPDATA%` |
| `--cdp-endpoint`, `--browserUrl` / `--browser-url`, `--wsEndpoint` / `--ws-endpoint` on another host | `warn` | the debugging protocol has no authentication, and the agent drives whatever browser listens there |
| the same switches on `localhost`, `127.0.0.1`, `::1` (also `PLAYWRIGHT_MCP_CDP_ENDPOINT`), or a `${VAR}` value | `info` | a browser on this machine started with a debugging port |
| `--connect-existing` (Firefox DevTools MCP) | `info` | connects to a Firefox already running on this machine |

Both spellings are read: `--flag=value` and `--flag value` as separate entries.

A debugging endpoint on this machine is `info` because Chrome 136 and later refuse `--remote-debugging-port` on the default profile: a browser that answers on a debugging port was started with a profile of its own, in practice a separate one for testing. `--autoConnect` and `--extension` are different: they join the browser the user is already logged in with.

## Measurement

On the 25,100-repository corpus, with 6,738 MCP config files (`.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json`, `.codex/config.toml`, OpenCode, Claude settings), the rule reports 36 servers in 25 repositories. 8 are `warn`, in 7 repositories: `--autoConnect` 5 times and `--extension` 3 times. 28 are `info`: debugging endpoints on `localhost` or `127.0.0.1`, and `--connect-existing`. None used a real browser profile or an endpoint on another host.

## Not flagged

- `--user-data-dir` on a project folder (`./misc/browser-storage`), which keeps the agent's browser state apart from the user's.
- `--no-sandbox`, `--headless`, `--isolated` and other launch switches.
- `--extension=false`, `PLAYWRIGHT_MCP_EXTENSION=false`, and a switch without a value.
- The same switch names on a server that is not a browser server.

## Trigger example

```json path=.mcp.json
{
  "mcpServers": {
    "browser": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest", "--autoConnect"]
    }
  }
}
```

→ `warn`: the agent drives the Chrome the user is logged in with.

## Safe alternative

Let the server start its own browser with an isolated profile (the default for Playwright MCP, `--isolated` for Chrome DevTools MCP). If the project needs a logged-in session, start a separate browser profile for the agent and log in to a test account there, and keep that setup in a developer's own machine-scoped config rather than in the repository.
