# CFG007 — hardcoded secret in `env` block

**Severity:** `error`
**OWASP:** [LLM02:2026 – Sensitive Information Disclosure](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM02_SensitiveInformationDisclosure.md)
**Agents:** claude-code

## What cfgaudit checks

cfgaudit flags any entry in `settings.json`'s `env` map whose value either:

1. **Matches a known credential format**:
   - vendor tokens by prefix, length and alphabet: Anthropic (`sk-ant-...`), OpenAI (`sk-...`, `sk-proj-...`), OpenRouter (`sk-or-v1-...`), GitHub (`ghp_...`, `gho_...`, `ghu_...`, `ghs_...`, `ghr_...`, fine-grained `github_pat_...`), GitLab (`glpat-...`, runner `glrt-...`), AWS access key IDs (`AKIA...`, temporary `ASIA...`), Amazon Bedrock API keys (`ABSK...`), Slack (`xoxb-...`), Google (`AIza...`), Stripe (`sk_live_...`, `rk_live_...`), Hugging Face (`hf_...`), npm (`npm_...`), PyPI (`pypi-...`), SendGrid (`SG....`), Twilio (`SK` + 32 hex), Databricks (`dapi` + 32 hex), HashiCorp Vault (`hvs.`, `hvb.`), Linear, Notion, Groq, xAI, Perplexity, Replicate, Grafana service accounts, Docker Hub, Shopify, Doppler, age secret keys, LangSmith, Pinecone, Tailscale, Atlassian, Postman, Figma, Sentry and Telegram bot tokens;
   - a PEM private key block (`-----BEGIN ... PRIVATE KEY-----`);
   - a Slack or Discord webhook URL, which is its own credential;
   - a connection string with a literal password (`postgres://user:password@host/db`) or an Azure `AccountKey=` / `SharedAccessKey=`. A password that is a reference or placeholder, a local development default (`postgres`, `password`, `root`, ... or the user name) and a loopback or local container host (`localhost`, `127.0.0.1`, `host.docker.internal`, `db`) are not flagged;
   - a JSON Web Token, except a Supabase anon key (`"role": "anon"` in the payload), which Supabase issues for public clients;
2. **Has a secret-like key name with a literal value**: keys ending in `_TOKEN`, `_SECRET`, `_PASSWORD`, `_PASSWD`, `_API_KEY`, `_PRIVATE_KEY`, `_ACCESS_KEY`, `_AUTH_KEY`, `_CREDENTIAL` or `_CREDENTIALS`, and the Claude Code variables that hold a credential under another name: `AWS_BEARER_TOKEN_BEDROCK` and `CLAUDE_CODE_CLIENT_KEY_PASSPHRASE`; or
3. **Is a header list carrying a credential**: `ANTHROPIC_CUSTOM_HEADERS` (newline-separated `Name: Value`) and `OTEL_EXPORTER_OTLP_HEADERS` / `OTEL_EXPORTER_OTLP_*_HEADERS` (comma-separated `name=value`, URL-encoded) are split into headers, and each header is checked like an MCP server's headers in [CFG050](CFG050.md): a known format, or a literal credential in an auth header or after `Bearer` / `Basic`.

Under a secret-like name, an unfilled placeholder is not flagged: `<your-token>`, `your-api-key`, `changeme`, values made only of capitals and underscores (`REDACTED`, `REPLACE_ME`, `YOUR_PAT_HERE`) and values containing `xxx`. The message names the kind of credential and never quotes the value.

Values that are a single shell-variable reference (`$FOO` or `${FOO}`), including the default form with an empty or referenced default (`${FOO:-}`, `${FOO-}`, `${FOO:-${BAR}}`), and empty values are not flagged. A literal default (`${TOKEN:-sk-live-...}`) commits the value and is flagged. Under a secret-like name, a value that is a file path (`/...`, `~/...`, `./...`, `C:\...`) is not flagged either: `GOOGLE_APPLICATION_CREDENTIALS` and its kind hold the path of a key file, and the file is not in the config (#852). A relative path with a directory and a file extension (`.codex/credentials/dev.json`) and a boolean switch (`"BRIDGE_PERSISTENT_SECRET": "true"`; true, false, yes, no, on, off) are not flagged either (#891).

Project-level `.claude/settings.json` is committed to version control. Any credential placed there is exposed to every repo collaborator, every CI pipeline that checks the repo out, and every public/private mirror.

### Permission entries (#1168)

Claude Code writes an approved command into `permissions.allow` as it was typed. A token exported or sent in a session therefore ends up in the allow list, and a committed `.claude/settings.json` or `.claude/settings.local.json` publishes it. CFG007 checks every entry of `permissions.allow`, `permissions.ask` and `permissions.deny` with the same detectors as the `env` block: a vendor key format anywhere in the entry, and a `NAME=value` assignment where the name looks like a secret and the value is a literal. A reference (`"$MY_TOOL_TOKEN"`), a placeholder (`<your-token>`) and a plain value (`NODE_ENV=production`) are not reported. The message names the list and the index, never the value, and says to rotate the key: removing the entry does not remove it from git history. In the pre-release corpus run for v1.20.0 on 10,034 repositories this found three entries in two committed `settings.local.json` files, which no rule reported before.

```json
{ "permissions": { "allow": ["Bash(export MY_TOOL_TOKEN=\"sk-...\")"] } }
```

→ `error`: "permissions.allow[0] contains a hardcoded OpenAI API key".

## Trigger example

```json path=.claude/settings.json
{
  "env": {
    "ANTHROPIC_API_KEY": "sk-ant-api03-...",
    "DEPLOY_TOKEN": "glpat-xxxxxxxxxxxxxxxxxxxx"
  }
}
```

## Safe alternative

Reference an environment variable from the shell instead of embedding the literal value:

```json
{
  "env": {
    "ANTHROPIC_API_KEY": "$ANTHROPIC_API_KEY",
    "DEPLOY_TOKEN": "${DEPLOY_TOKEN}"
  }
}
```

Or omit the entry entirely from `settings.json` and let Claude Code inherit it from the surrounding shell environment.
