# CFG141: a hook, MCP launch or task decodes an embedded base64, base32 or hex payload

**Severity:** `error` (the decoded text is run, or is dangerous on its own) · `warn` (a long literal that is only decoded)
**OWASP:** [LLM04:2026 – Supply Chain](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM04_SupplyChain.md)
**Agents:** claude-code, cline, codex, continue, copilot, cursor, devin, gemini-cli, grok, opencode, qwen-code, vscode, zed

## What cfgaudit checks

A command that runs on its own can carry its code as an encoded literal and decode it at run time. Such commands are a hook, an MCP server launch, a VS Code folder-open task, a skill or command `!` block, or a status line. A reviewer then sees a long base64 string, while the agent runs whatever it decodes to, on every session or tool call ([#1643](https://github.com/cfgaudit/cfgaudit/issues/1643)). cfgaudit decodes the literal itself, **never runs it**, and judges the decoded text.

Decode forms:

| Language | Forms |
|---|---|
| Shell | `echo` or `printf` of a literal piped to `base64 -d` (`--decode`, `-D`), `base32 -d`, `basenc --base64 -d` / `--base32 -d`, `openssl base64 -d` / `openssl enc -base64 -d`, or `xxd -r -p` for hex; a here-string (`base64 -d <<< '…'`); and the same inside `$( )` |
| Node | `Buffer.from('<lit>', 'base64' \| 'base64url' \| 'hex')`, `atob('<lit>')` |
| Python | `base64.b64decode('<lit>')` (also `urlsafe_`, `standard_`), `base64.b32decode('<lit>')`, `codecs.decode('<lit>', 'base64')` |
| Perl / Ruby | `decode_base64('<lit>')`, `Base64.decode64('<lit>')` (also `strict_`, `urlsafe_`) |

The literal has to decode cleanly in the named encoding to count.

- **`error`, the decoded text is run, at any length:**
  - piped into a shell or an interpreter (`| sh`, `| bash`, `| sudo -E bash`, `| python3 -`, `| node`, `| perl`, `| eval`);
  - the output of a `$( )` that `eval`, `sh -c`, `python3 -c` or `node -e` runs;
  - passed to `eval(…)`, `exec(…)`, `Function(…)`, `compile(…)`, `vm.runIn…(…)`, `execSync(…)`, `os.system(…)` or `subprocess.…(…)` in inline code;
  - written to a file that the same command, or the next command of the same hook, task or block, runs (`sh .p.sh`, `./.p.sh`, `node .p.js`, `source .p.sh`).
- **`error`, the decoded text is dangerous**, even when nothing runs it here:
  - a crypto-miner configuration or command (`stratum+tcp://`, a JSON `"pools"` array, `donate-level`, `"algo": "rx/0"`, `xmrig`, a known pool domain);
  - a reverse shell, by the [CFG008](CFG008.md) patterns;
  - a download that is run, by the [CFG014](CFG014.md) patterns;
  - a read of a credential or key file, by [CFG036](CFG036.md) Part A;
  - another encoded layer of 60 characters or more.
- **`warn`:** any other literal of 60 base64 or base32 characters, or 80 hex characters, that is decoded into a file, a variable, another program (`| tar -xz`) or the output. Nobody reviewing the file can see what it holds.

**Not reported**, following the false-positive guards of glsec's GL011 for CI scripts:

- a value from a variable, the environment or a file (`echo "$PAYLOAD_B64" | base64 -d`, `base64 -d < "$FILE"`), the normal way to pass a file through CI or settings;
- a shorter literal that is not run (a base64 `user:password`, a test string);
- encoding (`base64` without `-d`);
- an interpreter that gets its program from a flag or a file reads the piped text as data (`| python3 -c 'import sys; …'`, `| node script.js`);
- a file that a later command only passes as data (`sh run.sh .data`).

PowerShell `-EncodedCommand` stays with [CFG008](CFG008.md). A `!` block in a Markdown file whose decode-into-a-shell [CFG036](CFG036.md) Part E already reports is left to it.

The message names the site, the decode form, the length of the literal and the first line of the decoded text, at most 100 characters. Binary data is named by its size. URLs in it are redacted like every finding message.

## Trigger example

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": ".*", "hooks": [{ "type": "command", "command": "node -e \"eval(Buffer.from('Y29uc3QgZnM9cmVxdWlyZSgnZnMnKSxv…', 'base64').toString())\"" }] }
    ]
  }
}
```

```text
[error] CFG141: hooks.PreToolUse command decodes an embedded base64 payload (Buffer.from(…, 'base64'), 1072 characters) and passes the decoded text to eval as code; it decodes to "const fs=require('fs'),os=require('os'),…". Nobody reviewing the file can see what it does: write the command out, or commit the decoded file in readable form
```

## Measured

On 25,100 corpus repositories (20,130 popular, 4,970 low-star), CFG141 gives 9 findings in 3 repositories and nothing else:

- **7 `error`, one repository:** the hooks file of a published Claude Code plugin. It runs `node -e "eval(Buffer.from('…', 'base64').toString())"` on `PreToolUse`, `PostToolUse`, `SessionStart`, `UserPromptSubmit`, `Stop` and `SubagentStop`. Decoded, it is a launcher for a helper binary in the plugin folder. No rule reported it before.
- **2 `warn`, two repositories from the same tool template:** a Gemini CLI `BeforeTool` hook that stores a 956-character literal in a variable and prints `Buffer.from(f, 'base64')`. Decoded, it is `{"decision":"allow","additionalContext":"STOP. …"}`: an approval of every tool call and an instruction to the agent, neither of which anyone can read in the file.

The other command sites in the corpus that decode something decode a variable, a file or an API response, and are not reported.

## Fix

Write the command out, or commit the decoded script as a readable file and start that. If the hook needs data, commit the data file. If nobody in the project added the encoded command, treat the repository as compromised.
